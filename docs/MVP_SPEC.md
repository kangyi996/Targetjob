# Targetjob MVP 需求说明

## 1. 文档目的

这份文档描述 Targetjob 第一版 MVP 要做什么、不做什么，以及怎样判断它是否完成。

它是写代码前的“施工图”：先把产品行为说明白，再决定技术实现方式。

## 2. 核心用户问题

求职者拿到一个目标职位后，往往不知道：

- 这个职位真正看重哪些能力；
- 自己的简历里哪些内容与职位匹配；
- 哪些要求没有证据支持；
- 简历应该怎样针对这个职位调整；
- 面试时可能被问到什么。

Targetjob MVP 要解决的问题是：

> 帮助求职者理解目标职位，并根据自己的背景得到有依据、可执行的准备建议。

## 3. 目标用户身份

用户开始分析前，需要选择一种身份。身份会影响智能体的关注重点，但不会改变核心流程。

| 身份 | 重点关注 |
| --- | --- |
| 应届生 | 课程、校园项目、实习经历、基础技能和成长潜力 |
| 实习生 | 课程项目、社团经历、基础技能、学习能力和实习目标 |
| 转行者 | 可迁移能力、转行原因、技能缺口和职业变化解释 |
| 有工作经验的求职者 | 工作成果、业务影响、职责深度和专业能力 |

## 4. 用户故事

用户故事是从用户角度描述产品价值的简单句子。

### 4.1 主用户故事

作为一名求职者，我希望输入自己的简历和目标职位描述，并选择自己的求职身份，从而得到针对该职位的匹配分析和准备建议。

### 4.2 子用户故事

- 作为应届生，我希望知道校园项目如何对应职位要求；
- 作为实习生，我希望知道自己还需要补充哪些基础能力；
- 作为转行者，我希望知道哪些既有经验可以迁移到新职位；
- 作为有工作经验的求职者，我希望突出工作成果而不只是罗列职责；
- 作为求职者，我希望知道分析结论来自简历中的哪些内容。

## 5. MVP 用户流程

### 5.1 正常流程

1. 用户打开 Targetjob；
2. 用户选择求职身份；
3. 用户粘贴或输入简历文本；
4. 用户粘贴或输入职位描述文本；
5. 用户点击“开始分析”；
6. 系统检查输入是否完整；
7. 智能体提取职位要求和简历信息；
8. 智能体根据用户身份进行对比分析；
9. 系统展示求职分析报告；
10. 用户查看建议，并决定是否继续进行简历优化或面试准备。

### 5.2 第一版交互界面

第一版只需要包含以下内容：

- 身份选择区；
- 简历输入区；
- 职位描述输入区；
- 开始分析按钮；
- 加载状态提示；
- 分析结果展示区；
- 错误提示和重新分析入口。

## 6. 输入说明

### 6.1 必填输入

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `candidate_type` | 枚举 | `student`、`intern`、`career_changer` 或 `experienced` |
| `resume_text` | 文本 | 用户的简历内容 |
| `job_description` | 文本 | 目标职位描述 |

### 6.2 输入校验

- 必须选择一种身份；
- 简历不能为空或只有很短的无意义文本；
- 职位描述不能为空或只有很短的无意义文本；
- 如果输入不完整，系统需要告诉用户具体缺少什么；
- 第一版不要求用户上传 PDF 或 Word 文件，先使用文本输入降低实现复杂度。

## 7. 输出说明

分析报告至少包含以下部分：

1. 职位概览：职位的主要职责和核心要求；
2. 匹配优势：简历中与职位要求相符的内容；
3. 能力缺口：职位要求中暂时没有足够证据支持的内容；
4. 证据引用：说明结论对应简历中的哪些经历或技能；
5. 简历建议：针对当前职位应该补充、调整或重写的内容；
6. 面试准备：可能的问题、回答准备方向和需要准备的经历；
7. 身份专属建议：结合用户选择的身份给出额外提醒。

## 8. 不同身份的分析重点

核心报告结构保持一致，只有分析重点发生变化：

- 应届生：如果缺少正式工作经历，优先分析课程项目、校园项目和实习经历；
- 实习生：优先关注基础技能、学习能力、项目参与程度和实习目标；
- 转行者：优先识别旧行业经验中的可迁移能力，并帮助解释转行逻辑；
- 有工作经验者：优先关注量化成果、业务影响、职责范围和专业深度。

## 9. 系统状态

系统状态指用户操作过程中产品所处的阶段。

| 状态 | 用户看到的内容 |
| --- | --- |
| 初始状态 | 身份选择和两个输入框 |
| 校验失败 | 明确提示哪个输入缺失或无效 |
| 分析中 | 加载提示，防止用户误以为没有反应 |
| 分析成功 | 展示完整分析报告 |
| 分析失败 | 说明暂时无法完成，并提供重试入口 |

## 10. MVP 验收标准

满足以下条件，就认为第一版 MVP 基本完成：

- 用户可以选择四种身份中的任意一种；
- 用户可以输入简历和职位描述；
- 输入不完整时，系统能给出明确提示；
- 输入完整时，系统能完成一次分析；
- 报告包含匹配优势、能力缺口、简历建议和面试准备；
- 更换身份后，报告的重点建议会发生合理变化；
- 分析失败时，用户能够看到可理解的错误提示；
- 使用同一组测试数据重复分析时，报告结构保持稳定。

## 11. MVP 暂不包含

- 用户注册、登录和权限系统；
- PDF、Word 等文件解析；
- 自动抓取招聘网站；
- 自动投递职位；
- 复杂的职位收藏和进度管理；
- 长期保存用户简历；
- 多智能体并行协作；
- 复杂的推荐算法和职位排序。

这些功能可以在 MVP 验证核心价值之后再规划。

- 使用什么模型服务；
- 采用网页界面还是先做命令行界面；
- 是否需要数据库；
- 如何记录测试样例和评估结果。
